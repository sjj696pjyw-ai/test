# Прогон сбора товаров на хосте

Массовая проверка алгоритма парсинга по реальным сайтам: сколько товаров,
каким тиром, за какое время, с примерами названий и цен и сравнением
с предыдущим прогоном.

Зачем на хосте, а не локально: у сервера другой канал, провайдер и мощности —
часть сайтов локально не открывается или ведёт себя иначе.

## Подготовка (один раз)

В переменных окружения приложения на Amvera задайте секрет:

```
ADMIN_TOKEN=<длинная случайная строка>
```

Без этой переменной служебные эндпоинты полностью отключены (отдают 404).
Сгенерировать токен: `python -c "import secrets; print(secrets.token_urlsafe(32))"`

## Запуск прогона (с вашей машины, выполняется на сервере)

```sh
TOKEN=<ваш ADMIN_TOKEN>

# запустить прогон всего набора (ответ приходит сразу, сбор идёт в фоне)
curl -X POST https://pricemonitor.tech/api/admin/bench \
     -H "X-Admin-Token: $TOKEN" -H "Content-Type: application/json"

# только по части сайтов
curl -X POST https://pricemonitor.tech/api/admin/bench \
     -H "X-Admin-Token: $TOKEN" -H "Content-Type: application/json" \
     -d '{"only": ["e2e4", "mokry"]}'

# идёт ли прогон и сколько сайтов уже обработано
curl -H "X-Admin-Token: $TOKEN" https://pricemonitor.tech/api/admin/bench/state

# короткая сводка последнего отчёта (читаемая в терминале)
curl -H "X-Admin-Token: $TOKEN" https://pricemonitor.tech/api/admin/bench/summary

# полный отчёт (JSON со всеми примерами товаров и сравнением)
curl -H "X-Admin-Token: $TOKEN" https://pricemonitor.tech/api/admin/bench/last
```

Прогон идёт минуты (крупные каталоги вроде e2e4 — до полутора минут каждый),
поэтому запуск асинхронный: HTTP-ответ приходит мгновенно, а ход прогона
виден в логах приложения по метке `[БЕНЧ]`:

```
[БЕНЧ] старт прогона: сайтов 8
[БЕНЧ] 1/8 e2e4 (ноутбуки): 1002 товаров (dom), 41.0с
[БЕНЧ] готово: OK 6, WARN 1, FAIL 1, время 154.2с, отчёт bench_20260728_120000.json
[БЕНЧ] РЕГРЕСС — rus-buket (розы): товаров меньше на 18
```

## Запуск локально (если нужно)

```sh
cd backend
python scripts/bench_collect.py                    # весь набор + сравнение
python scripts/bench_collect.py --only e2e4        # выборочно
python scripts/bench_collect.py --no-compare
```

Код возврата 1, если найдены регрессии — годится для cron/CI.

## Как читать результат

- **OK** — товаров не меньше ожидаемого, способ сбора совпадает с ожидаемым.
- **WARN** — товаров меньше `expect_min` или сменился способ сбора.
- **FAIL** — ноль товаров или ошибка.
- **РЕГРЕСС** — по сравнению с прошлым прогоном сайт перестал парситься или
  товаров стало меньше более чем на 10%. Именно это ловит поломки, внесённые
  правкой алгоритма ради другого сайта.

Диапазон цен (мин/макс/медиана) в отчёте помогает заметить брак разбора:
например, склейку цены с цифрой из названия или единственный бракованный товар.

## Набор сайтов

`backend/scripts/bench_sites.json`. Пополняйте — чем шире набор, тем раньше
видно поломки. Поля: `name`, `url`, `expect_min`, `expect_method`, `note`.

## Отчёты

Складываются в `backend/scripts/reports/`. Каждый следующий прогон
сравнивается с последним сохранённым.

Важно: на Amvera файлы вне примонтированного тома не переживают пересборку.
Чтобы отчёты сохранялись между деплоями, укажите путь на постоянном диске:

```
BENCH_REPORTS_DIR=/data/bench-reports
```
